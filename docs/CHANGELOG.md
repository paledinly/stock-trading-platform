# Changelog

사용자와 운영에 영향을 주는 주요 변경만 기록한다. 단계별 AI 작업 로그는 Git 이력과 audit에 보존한다.

## 2026-10-15

- KIS 실패 기록 보강(동작 변화 없음): 공통 요청 장치가 재시도 후에도 실패한 요청마다 HTTP 상태·KIS 오류 코드(`msg_cd`)·짧은 설명(`msg1`)을 경고 로그(`KIS request failed status=500 msg_cd=EGW00201 ...`)로 남기고, 시장 스캔 수집 요약의 `kisRequests`에 `failure.<코드>` 수를 더한다. 투자자 수급 수집 실패 로그와 상태(`failureCodes`)에도 같은 정보를 남긴다. KIS가 호출 한도 초과(`EGW00201`)를 HTTP 500으로 돌려줄 때 예외 이름만 남아 원인을 구분할 수 없던 문제 때문이며, HTTP 500 + `EGW00201`을 재시도할지는 기록을 본 뒤 정한다.
- Web 화면 개편 1단계: 오른쪽에 떠 있던 메뉴와 초보자/고급 모드를 왼쪽 메뉴(운영·탐색·검증·기록)로 바꾸고, 화면별 해시 주소(`#/closing` 등)를 붙였다. 마감 추천은 예전 고급 모드 내용을 모두 보여 준다. 모든 색을 `theme.css` 토큰으로 바꿔 밝은 화면을 추가했다(저장값이 없으면 운영체제 설정을 따른다). 화면 제목 크기를 맞추고 '←대시보드' 버튼과 'N단계' 표기를 없앴다. 실시간 레이더의 연결 상태를 빨간 '연결중' 대신 초록 '연결됨'으로 표시한다.
- 대시보드: 왼쪽 패널을 '관심종목 | 실시간 구독' 탭으로 나눠, 구독 종목을 눌러도 위로 올라가지 않고 오른쪽 고정 차트에서 바로 본다(마지막 탭은 탭이 열려 있는 동안 기억). 관심종목 그룹 이름 변경과 삭제(확인 후, 안의 종목과 실시간 고정도 함께 삭제)를 추가했다. 5분봉 차트 시간축을 UTC가 아닌 한국 시간으로 표시한다.
- Web 기본 화면 '오늘'(운영 현황): 하루 자동 작업 시간표와 작업별 상태(정상·확인 필요·문제·진행 중·예정), 실시간·구독·시장 스캔·연구 수급 요약, 최근 일별 완결성 표. 판정은 보기용이며 공식 판정은 15:45 일별 완결성 기록이다. 이를 위해 조회 전용 `GET /closing-recommendations/daily-collection`을 추가했다(Backend 재시작 후 사용 가능, 이전에는 해당 항목을 '재시작 후 표시'로 보여 준다). 08:10 후보 일봉 준비는 실행 기록이 없어 '기록 없음'으로 표시한다.
- 마감 추천 화면 재배치: 위에서부터 조회 줄(추천일·평가 이력·run 정보·최근 완결성) → 평가 요약 숫자와 제한 모드·제외 사유 안내 → 추천 랭킹 순으로 보여 주고, 전체 후보 관측·생성 당시 후보 평가·검증 요약·일별 수집 완결성·도구(후보 평가 실행, 성과 추적, 매도/보유 판단, 오버나잇 백테스트, 일봉 준비)는 접는 영역으로 옮겼다. 평가가 있었지만 최종 추천이 0건인 날은 '추천 생성을 실행하세요' 대신 제외 사유를 보라고 안내한다. 기능과 API 호출은 바꾸지 않았다.
- 나머지 화면 정리: 시장 스캐너는 화면을 열어도 수동 스캔(KIS 조회·정밀 구독 배정 반영)을 하지 않고 버튼을 누를 때만 실행한다. 백테스트도 '재생'을 눌러야 실행하고 가상 탐지 목록은 30건씩 더 보기로 나눈다. 성과 분석은 표본 수만으로 정하는 '신뢰도'를 '표본 충분/관찰/부족'으로 표시하고 '실제로 우위가 있는 신호' 문구를 지웠다. 성과 분석·백테스트 기본 날짜를 한국 날짜로 계산한다. 실시간 레이더는 탐지 설정을 접는 목록으로 바꾸고 삭제 전 확인을 받으며, 레이더 화면에서 SSE 연결이 두 개 열리던 것을 하나로 합쳤다. 투자기록 삭제 전 확인을 추가했다. 왼쪽 메뉴 때문에 중간 폭(1100~1600px)에서 레이더 3열이 가로로 넘치던 배치를 2열로 바꿨다.
- 왼쪽 메뉴 꾸밈: 메뉴별 선 아이콘, 선택 메뉴 강조 막대, 로고 정리, 아래쪽 장 상태 칸(장 구간·실시간 연결·다음 자동 작업까지 남은 시간), 밝게/어둡게 두 칸 스위치. 투자기록은 새 거래 기록을 좁은 왼쪽 칸으로 줄이고 거래 내역을 넓은 오른쪽 칸에서 같은 높이로 시작하게 바꿨다.

## 2026-10-14

- 분봉 보충을 별도 예약 작업이 아닌 15:40 후보 관측 직전 호출로 옮겼다. 첫날 예약 작업이 실행 흔적 없이 돌지 않았다. 상한가 직전 매수 연구 수집은 등락률 순위가 +29.93% 종목을 놓쳐, 최근 10분 시장 스캔 스냅샷을 두 번째 출처로 더하고 출처·순위 응답 건수를 기록한다(V36).
- 외부 요인 기록(V35, 점수 미사용): 공식 평가 직후 후보의 시장경고·투자유의·VI·단기과열·정리매매·관리·임시정지 상태(`closing_candidate_context`)와 DART 공시 목록(`dart_filing`, `DART_API_KEY` 필요)을 저장한다.
- 실시간 구독: 보호 구독(관심종목 고정·수동·다음날 관측) 뒤 남은 자리를 모두 정밀 구독에 배정(상한 28→41, 예비 3→0). 대시보드에 '실시간 구독' 표(종목·출처·상태·정밀 점수·편입 시각)를 추가했다. 시장 전체 스캔의 정밀 후보 상한을 30→41, 현재가 조회 예산을 30→45로 늘렸다. 보호 구독이면서 정밀인 종목을 용량에서 두 번 빼던 계산과, 화면 시세 조회가 실시간 자리를 해제 없이 차지하던 동작도 고쳤다. 구독 직후 늦게 기록된 대기 상태가 확인된 구독을 덮어 '대기'로 보이던 표시 오류를 고쳤다.
- 상한가 직전 매수 연구 수집(V34 `limit_up_watch`, 기본 비활성): 15:16·15:18에 +20% 이상 종목의 호가를 저장해 15:20 전 매수 가능 여부를 기록한다. 사전 등록 `audit/2026-10-14-limit-up-entry`.
- 마감 추천 1차 표본을 정밀 후보 전체로 변경(ADR-010). 실시간 구독을 받지 못한 정밀 후보의 다음 거래일 5분봉은 장 마감 후 KIS 분봉으로 채운다(15:40 후보 관측 직전). 분봉 보충은 15:30 종가 단일가 체결 분봉을 15:25 봉에 합치고, 동시호가 무체결 분봉은 버린다.

## 2026-10-13

- 수정주가 일봉 수집(V33, 연구용): ETF·ETN 제외 전 종목의 수정주가 일봉을 `daily_adjusted_candle`에 모은다. 시점 기준 Universe로 하룻밤 보유를 다시 검증하기 위한 것이며, 운영 마감 추천의 일봉(원주가)은 바꾸지 않는다. 기본 비활성, 수동 시작 API 제공.
- 탐지 성과 저장: 행마다 따로 저장해, 한 행의 낙관적 잠금 충돌이 같은 묶음의 다른 성과 갱신과 15:31 마감 확정을 막지 않게 했다. 충돌한 행은 DB에서 다시 읽고 저장된 봉으로 복원한다. 2026-10-13 Supabase 업그레이드 중 DB에는 반영됐지만 응답이 끊긴 저장 이후, 13:55 탐지 3건이 매초 충돌했다.
- 마감 추천 v9.1(`closing-recommend-v9_1-1515`): 15:15 입력 마감 이후 수신된 탐지와 15:15:00에야 끝나는 15:10 봉을 늦은 수정이 아닌 미가용 입력으로 제외한다. 점수·필터·평가 시각은 v9와 같고 ADR-008 표본은 v9.1부터 다시 센다([ADR-009](decisions/ADR-009-CLOSING-V9_1-INPUT-AVAILABILITY.md)).
- Scanner 쿨다운: Redis가 없거나 실패하면 탐지를 버리지 않고 프로세스 내부 쿨다운으로 대체한다. 실시간 상태의 `scannerCooldownFallbacks`, `lastScannerCooldownFallbackAt`과 오류 목록(분당 1회)으로 확인한다. 일별 완결성은 평가 구간 탐지 0건을 `SCANNER_DETECTIONS_MISSING`으로 표시한다.
- 종가 단일가 체결 수신·저장: 원천시각 15:30:00~15:31:00(랜덤엔드) 체결을 수락해 15:25 봉에 반영하고, 전일 run 종목 구독을 15:31까지 유지하며, WebSocket 종료 유예 기본값을 2분으로 늘렸다. 이전에는 15:30:00 초과 체결을 조용히 버려 실시간 15:25 봉이 저장되지 않았다. 실시간 상태에 `closingAuctionTicks`, `outsideSessionTicks` 진단을 추가했다.
- 다음 거래일 세션 완결성 규칙 변경: 09:00~15:15 봉 + 거래량 있는 15:25 종가 체결 봉. 15:20 봉은 요구하지 않고, 15:32 전에는 `IN_PROGRESS`다. 공식 성과·후보 관측·ADR-008 judge에 같이 적용하며 저장된 과거 결과는 수정하지 않는다([전략 문서](TRADING_STRATEGY.md#다음-거래일-세션-완결성)).
- 장중 추천 기능 제거: 7세션 비교에서 비용 후 기대값이 양수가 되지 않고 목표 선도달률이 무작위 기준선보다 낮아 `intraday` 백엔드 모듈, `/api/v1/intraday/*` API, SSE `intraday.entry-ready`, 장중 추천 화면, `INTRADAY_*` 설정을 삭제했다([진입 비교](../audit/2026-10-13-intraday-entry-comparison/README.md), [실패 분석](../audit/2026-10-13-intraday-failure-analysis/README.md)). 마감 추천에 집중한다.
- `intraday_input`(9,346,586행, 13.3GB)은 로컬 백업과 행 수·최대 id를 대조한 뒤 2026-10-13 13:36 KST경 비웠다(TRUNCATE). DB는 13.64GB에서 0.37GB가 됐다([보관 기록](../audit/2026-10-13-intraday-archive/README.md)). 테이블 정의와 `intraday_recommendation`(약 7MB)은 남아 있다.
