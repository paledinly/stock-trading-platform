# ADR-009: 마감 추천 v9.1 — 평가 시점에 없던 입력 제외

Date: 2026-10-13

## 배경

`closing-recommend-v9-1515`의 공식 FORWARD run(10-08, 10-12)은 최종 추천을 하나도 만들지 않았다([원인 분석](../../audit/2026-10-13-closing-zero-selected/README.md)). 직접 원인 중 하나는 v9 설정(`featureFreezeAt=15:15`, `candleFinalizationGrace=0s`)과 평가 코드가 맞물린 측정 결함이다.

- 15:10 봉은 15:15:00에 끝나므로 15:15:00 이전에 저장될 수 없다. 평가 코드는 이 봉을 "평가 시점에 없던 봉"으로 건너뛰는 데서 그치지 않았다. 마지막 사용 봉 뒤에 있다는 이유로 `lateCandleRevision`으로 표시해 후보를 `RECEIVED_AFTER_EVALUATION`(WATCH)으로 보냈다. 관측된 11거래일 모두 정밀 후보의 73~100%가 이 조건에 걸렸다.
- 15:10 봉 마감 탐지(탐지시각 15:15:00)는 항상 15:15:00 이후에 수신된다. 이 탐지가 종목의 대표 탐지가 되면 같은 종목의 이전 정상 탐지를 가렸다.

[전략 문서](../TRADING_STRATEGY.md)는 이미 "15:15에 끝나도 그 이후 확정된 봉은 제외한다"고 정했다. 코드가 그 원칙과 달랐다.

## 결정

새 버전 `closing-recommend-v9_1-1515`로 등록한다. 요청 키 형식(`[A-Za-z0-9_-]`) 때문에 점 대신 밑줄을 쓴다. 바뀌는 것은 입력 가용성 규칙 하나다.

| 입력 | v9 | v9.1 |
| --- | --- | --- |
| 입력 마감(`featureFreezeAt + grace`) 이후 수신된 탐지 | 대표 탐지가 될 수 있고, 그러면 종목이 `RECEIVED_AFTER_EVALUATION` | 평가 입력에서 제외. 마감 전에 수신된 같은 종목의 최신 탐지가 대표가 된다 |
| 입력 마감 시각에야 끝나는 봉(유예 0초에서 15:10 봉) | 늦은 수정(`lateCandleRevision`)으로 표시 | 입력이 아니므로 제외. 늦은 수정이 아니다 |
| 입력 마감 전에 끝났지만 마감 후 저장·수정된 봉 | 늦은 수정 | 그대로 늦은 수정 |

- 점수, 필터, 임계값, 평가 시각(15:15), 유예(0초), 진입 모델, 비용은 v9와 같다. 결과를 보고 고른 값이 없다.
- run 설정에 `inputAvailability=EXCLUDE_UNAVAILABLE_AT_RECEIPT_DEADLINE`을 기록해 설정 해시로도 구분한다.
- 유예가 0보다 크면 마감 시각에 끝나는 봉이 유예 안에 저장될 수 있으므로 봉 규칙은 바뀌지 않는다. v8처럼 10초 유예를 둔 설정에서는 탐지 규칙만 적용된다.

## 판단 기준

ADR-008의 평가 대상, 비교안(BASELINE, NEXT_OPEN), 체크포인트, 판정 규칙을 그대로 v9.1에 적용한다. 표본은 v9.1 공식 FORWARD run부터 0건에서 센다. v9의 1차 표본은 0건이라 잃는 표본은 없다.

## 결과

- 15:10 봉과 15:15:00 탐지 때문에 정상일에 후보 전원이 WATCH가 되던 결함이 사라진다. 원인 분석 기준으로 기대 선정 수는 약 0.9건/일이다. ADR-008이 가정한 "하루 최대 5건, 3~6주"보다 훨씬 느리다. 표본 정의를 바꿀지는 별도 ADR로 정한다.
- 15:15:00 탐지는 그날 평가에 쓰이지 않는다. 그 정보는 15:15 평가 시점에 존재하지 않았다.
- v9 run과 v9.1 run은 같은 표본으로 합치지 않는다.
