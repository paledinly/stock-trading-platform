# ADR-011: 추천 경로에 LLM을 넣지 않는다

Date: 2026-11-03

## 배경

[외부 검토](../../audit/2026-11-03-external-review-brief/REVIEW.md)는 "LLM 판단 로직은 문서에 없다"고 적고, 도입한다면 학습 시점 이후 데이터만 입력하고 모델·프롬프트 버전을 기록하라고 권했다. 뉴스·공시 요약 같은 LLM 판단을 후보 평가에 더할지 결정이 필요했다.

## 결정

**종목 선정, 점수, 진입·청산 판단에 LLM을 쓰지 않는다.** 운영 마감 추천, 구독 선정, 그림자 Forward 모두 해당한다.

## 이유

- **과거 데이터로 공정하게 평가할 수 없다.** 범용 LLM은 학습 데이터에 평가 기간의 뉴스, 주가, 사후 해설이 들어 있을 수 있다. 2018~2026 백테스트에서 LLM이 내린 판단은 결과를 이미 아는 상태의 판단일 수 있고, 그 정도를 측정할 방법이 없다.
- **검증 방법과 맞지 않는다.** 이 프로젝트의 기준은 사전 등록, 동일 조건 비교, 날짜 블록 재표본이다([ADR-008](ADR-008-CLOSING-V9-DECISION-CRITERIA.md)). LLM은 백테스트로 평가할 수 없으니 Forward로만 검증해야 한다. 40거래일 Forward의 검정력도 낮은데(그림자 Forward 알려진 한계), 비교안을 늘리면 판정이 더 늦어진다.
- **재현이 어렵다.** 모델 버전이 바뀌거나 출력이 확률적이면 같은 날의 판단을 다시 만들 수 없다. 고정된 LightGBM 모델 파일(`audit/2026-11-03-shadow-forward/model.txt`)과 다르다.

## 허용하는 것

- 개발 보조(코드 작성, 문서 정리, 결과 검토). 이번 외부 검토도 여기에 해당한다.
- 추천 결과에 영향을 주지 않는 설명 문구. 다만 점수·선정·필터에 되먹임하지 않는다.

## 다시 검토하는 조건

다음을 모두 갖춘 사전 등록 문서가 있을 때만 새 ADR로 다시 검토한다.

- 모델 학습 데이터 기준일보다 뒤의 기간만 평가에 쓴다(사실상 Forward).
- 모델 이름·버전, 프롬프트, 온도 등 설정을 고정하고 기록한다.
- 기존 방식과 같은 Universe·진입·청산·비용으로 같은 날짜에 병행 기록한다.
