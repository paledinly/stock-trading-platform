# 오버나잇 후보 심사 및 전략 검증 개편 계획

작성일: 2026-09-17
상태: 설계 제안. 이 문서 작성으로 프로그램 동작이나 DB가 변경되지는 않는다.

## 1. 목표와 범위

현재의 장중 강세 탐지 기능을 후보 발굴에 활용하고, 매수 적격 심사와 모의 체결 및 성과 검증을 분리한다. 최종 목표는 높은 추천점수가 아니라 새 검증 기간에서도 확인되는 비용 차감 후 수익과 통제 가능한 계좌 손실이다.

```text
장중 탐지 / 시장 전체 후보
  -> 판단 시점의 후보군 고정
  -> 최신 데이터 및 매수 적격 심사
  -> 후보 순위 / 업종·계좌 한도 적용
  -> 모의 주문 또는 매수 보류
  -> 체결 / 미체결 기록
  -> 다음 거래일 청산
  -> 거래별 순손익 / 계좌 손익 / 벤치마크 비교
  -> 별도 기간 검증 후 전략 채택 또는 기각
```

- 기존 KIS 수집, 캔들 저장, 레이더, BROAD 후보 발굴은 유지한다.
- 기존 점수는 당일 강세를 설명하는 참고 지표 및 비교 전략으로 보존한다. 수익 확률로 표시하지 않는다.
- 자동 실주문, 딥러닝, 다수의 기술지표 추가는 이번 개편의 기본 범위에 포함하지 않는다.
- 추천 0건과 모의 매수 0건을 정상 결과로 취급한다.
- 이하 Phase 10A~10G는 이번 개편을 위한 제안 명칭이며 기존 Phase 9 완료 여부를 변경하지 않는다.

## 2. 현재 코드에서 확인한 수정 근거

| 위치 | 현재 동작 | 필요한 변경 |
|---|---|---|
| `ClosingRecommendationService.representativeCandidates` | 적격 여부와 높은 점수를 우선해 과거 탐지 선택 | 종목 발견 근거와 판단 시점의 최신 평가를 분리 |
| `ClosingRecommendation` 생성자 | 탐지 가격을 매수 기준가로 복사 | 신호 가격, 주문 기준 가격, 실제/모의 체결 가격을 구분 |
| `ClosingRecommendationService.generate` | 같은 날짜의 판단·성과·추천 삭제 후 재생성 | 실행 단위 이력 보존, 과거 체결 연결 유지 |
| `ClosingRecommendationRun` | 생성 응답 JSON 감사 기록 | 실행 모드, 설정, 데이터 시점, 후보·거래 연결 추가 |
| `ClosingRecommendationScorer` | 기존 기회점수와 VWAP·거래량·고점 근접도를 중복 가산 | 비교 전략으로 보존하고 신규 적격 심사와 분리 |
| `precisionMissing` | 일봉 준비 상태는 필수 조건 아님 | 일봉을 사용하는 전략에서 준비 상태·최신성 검사 |
| `ScannerEvaluator` | VWAP 회복 탐지에 이전 하회 상태 확인 없음 | 회복 전략 사용 시 실제 상태 전이와 유지 여부 검사 |
| `OvernightPerformanceService` | 마지막 확정 봉을 종가로 보고 완료 처리 | 장중 표시, 데이터 완결성, 최종 일일 성과 분리 |
| `OvernightBacktestService` | 운영과 다른 후보 선택, 고정 손절률 체결 가정 | 운영과 같은 평가 규칙 및 현실적 체결 모형 적용 |
| `MarketSessionPolicy` | 주말·설정 휴일과 스캐너 실행 시간 검사 | 다음 거래일·세션별 평가에 사용할 거래 일정 분리 |
| `Stock` | 업종 및 업종 분류 유효기간 없음 | 검증 가능한 업종 매핑과 적용 시점 확보 |
| `Trade`, ADR-007 | 개인 투자기록, 평균단가 회계, 비용·주문체결 미지원 | 기존 개인 기록과 분리된 모의운용 기록 설계 |

2026-09-17 조회 시 9/1~9/16 추천 48건 중 성과 기록은 38건, 전략 버전은 4개였다. 저장된 추천 사유에서 48건 모두 일봉 특징이 미준비 상태였고, 성과 34건은 다음 거래일 장 종료 전에 평가됐다. 이 수치는 진단 시점의 저장 상태이며 실제 체결 성과나 현행 단일 전략의 확정 성과가 아니다.

## 3. 용어와 상태 설계

### 후보 심사와 전략 검증은 별개다

| 구분 | 제안 상태 | 의미 |
|---|---|---|
| 후보 | `WATCH`, `ELIGIBLE`, `EXCLUDED` | 관찰, 규칙 통과, 제외 |
| 주문 | `PENDING`, `FILLED`, `PARTIAL`, `EXPIRED`, `REJECTED` | 주문 및 체결 결과 |
| 포지션 | `OPEN`, `CLOSED` | 실제로 체결되어 보유하거나 청산한 상태 |
| 관측 성과 | `PENDING`, `IN_PROGRESS`, `COMPLETE`, `DATA_INCOMPLETE` | 다음 날 시장 데이터의 완결 상태 |
| 전략 검증 | `RESEARCH`, `FORWARD_TESTING`, `REVIEW_REQUIRED`, `ACCEPTED`, `REJECTED` | 검증 절차의 진행 및 채택 상태 |

적격 후보는 수익성이 입증된 종목이라는 뜻이 아니다. 전략 채택도 미래 수익 보장이 아니다. 주문 상태와 다음 날 전체 시장 관측 상태는 별도이며, 09:30 청산 거래는 완료됐어도 당일 종가 관측은 진행 중일 수 있다.

### 실행 모드

- `FORWARD`: 실제 판단 시각에 확보된 데이터로 평가하고 이후 체결을 관측한다.
- `REPLAY`: 과거 데이터를 재구성해 평가한다. 이후 내려받은 과거 캔들은 당시 실시간 수신 데이터와 구분한다.
- `LEGACY`: 기존 추천·성과. 원본을 보존하며 신규 검증 기본 집계에서 분리한다.

장 종료 후 과거 날짜로 생성한 결과를 FORWARD로 분류하지 않는다. 판단 기한을 넘긴 실행도 과거 가격으로 매수시키지 않고 기한 초과 또는 재생 실행으로 남긴다.

## 4. 최초 검증 전략의 명세

가설: 전일까지 상승 추세였고 장 후반에도 강세가 유지되는 종목이 같은 보유 시간의 비교 대상보다 유리한 순수익을 낼 수 있는가?

아래는 실험 설계 초안이다. 수치의 수익성이 확인됐다는 뜻은 아니며, 각 실험 시작 전에 설정을 고정한다.

| 항목 | 제안 |
|---|---|
| 후보군 | 해당 시점에 관측한 PRECISION 및 BROAD 종목의 합집합을 종목 단위 중복 제거 |
| 데이터 수준 | BROAD 단독 순위 정보로 매수시키지 않고 동일한 필수 데이터 심사 적용 |
| 판단 시각 | 최초 실험은 15:15 KST를 예시로 설계. 현행 15:20 freeze와 별개이므로 모든 경로에서 같은 설정 사용 |
| 진입 시각 | 평가 완료 이후, 사전 정의한 주문 기한과 거래 세션 안에서 체결 가능한 시점 |
| 일봉 조건 | 전일까지의 종가 > MA20, MA20 상승. 상승 계산에 필요한 최소 21개 유효 일봉 확보 |
| 분봉 조건 | 판단 이전에 확정·수신된 최근 5분봉의 VWAP 위 유지 및 최신 상태 확인 |
| 순위 | 적격 후보 내 하나의 단순 순위 기준부터 검증. 초기 기준은 판단 시점까지의 상대 강도 |
| 종목 수 | 최대 3개를 실험 초안으로 사용. 동일 업종 최대 1개 |
| 투자 비중 | 모의 계좌의 총 투자 한도와 종목별 한도를 사전 고정. 미배정 금액은 현금 유지 |
| 청산 | 다음 거래일 09:30 이후 최초 실행 가능한 가격을 기준으로 하는 시간 청산부터 검증 |
| 손절 | 진입 시 정한 동일 규칙을 적용하되 갭 및 체결 지연 반영. 실험 중 손절폭 변경 금지 |
| 후보 없음 | 주문 없음. 탈락 이유와 현금 상태 기록 |

데이터 준비 조건과 거래 가능 조건은 필수다. 일봉 추세, VWAP 유지, 시장 환경 및 과열 필터는 각각 제거했을 때와 비교하여 효과를 검증한다. 새로운 조건을 모두 한꺼번에 추가해 효과를 추측하지 않는다.

실제 주문 세션과 동시호가를 지원하는지 명시한다. 5분봉 다음 봉 시가가 주문 가능한 세션 밖이거나 체결 모형이 지원하지 않는 동시호가에 해당하면 그 가격으로 임의 체결시키지 않는다. 필요하면 실험 판단 시간을 앞당기되 변경한 설정은 새 실험으로 취급한다.

## 5. Phase 10A: 이력 보존과 성과 정합성 [P0]

### Backend / DB

- `generate`의 날짜 단위 삭제를 제거하고 실행 ID별로 후보·성과를 연결한다.
- `closing_recommendation_run`에 실행 모드, 판단 시각, 평가 완료 시각, 설정 스냅샷·해시, 알고리즘/데이터 버전을 추가한다.
- `closing_recommendation`에 run ID를 추가한다. 기존 날짜+종목 유니크 제약은 이관 후 실행+종목 기준으로 교체한다.
- 기존 추천과 연결 성과·매도 판단은 삭제하거나 ID를 재작성하지 않는다. 기존 행은 LEGACY 실행에 연결한다.
- 재시도 식별키를 저장해 동일 요청의 중복 실행을 막고, 의도적인 재평가는 새로운 run으로 보존한다. 실패한 실행이 반쪽 상태로 노출되지 않게 트랜잭션 경계를 정한다.
- 다음 거래일은 거래 일정으로 결정한다. 예상 거래일 캔들이 없다고 그다음 데이터가 있는 날짜로 조용히 넘기지 않는다.
- `observedThrough`, `expectedSessionDate`, 세션 시작·종료 및 누락 구간을 기록한다.
- 다음 날 전체 관측이 끝나기 전에는 최종 종가·COMPLETE로 표시하지 않는다. 장 종료 후에도 누락 봉이 있으면 불완전 상태다.
- 목표 도달/손절 도달은 독립 필드로 보존하고 실제 청산 사유와 구분한다.

### Frontend / API

- 조회에 run ID를 사용할 수 있게 하고 기존 날짜 조회는 선택된 실행의 결과임을 명시한다.
- 기존 '추천 생성'은 '후보 평가', 기존 '매수 기준가'는 '신호 가격'으로 의미를 정리한다.
- 장중 관측 수익과 최종 관측 수익을 분리하고 데이터 기준 시각을 표시한다.
- 구버전 결과는 '기존 계산'으로 구분한다. 목표·손절 모두 도달한 경우 둘 다 표시한다.

### 완료 기준

- 동일 날짜를 재평가해도 기존 성과·판단 및 연결 ID가 유지된다.
- 오전 09:13 평가가 다음 날 종가 성과 완료로 표시되지 않는다.
- 주말, 설정된 휴장일, 다음 거래일 데이터 누락, 장 마감 봉 누락을 구분한다.
- 과거 실행을 현재 데이터로 다시 계산해 원본 성과를 덮어쓰지 않는다.

## 6. Phase 10B: 동일 시점 데이터와 공통 평가 [P0]

### Backend / 수집

- `ClosingRecommendationService`와 `OvernightBacktestService`가 같은 후보 심사·순위 함수를 사용하도록 최소 범위로 추출한다. 데이터 조회·저장과 순수 평가만 분리하고 범용 전략 프레임워크는 만들지 않는다.
- 후보를 발굴한 과거 탐지와 평가 시점 특징을 별도 저장한다. 과거 최고점 탐지로 현재 상태를 대체하지 않는다.
- 데이터의 시장 시각과 수신 시각을 구분한다. FORWARD 판단은 해당 시점까지 실제 수신 완료된 데이터만 사용한다.
- 종목별 일봉 준비 수·마지막 거래일, 분봉 연속성·최종 확정 시각, 실시간 특징 최신성 검사 결과를 저장한다.
- 기존 일봉 수집 경로의 저장 여부, `1D` timeframe, 날짜 경계, 수정주가 기준을 조사한다. 저장 사유의 candleCount=0만으로 전체 DB 일봉 부재라고 단정하지 않는다.
- 60일선 사용 전략은 별도의 최소 일봉 수를 요구한다. 최신 일봉 지연이나 필수 특징 결손을 0점/무위험으로 처리하지 않는다.
- 과거 데이터 정정·백필 이후의 재생 결과는 데이터 버전을 변경한다. 당시 수신 상태를 복원할 수 없는 기간은 그 한계를 표시한다.
- KIS 호출 제한 내에서 후보 데이터 보강을 수행한다. 큐, 재시도, 캐시를 재사용하고 모든 관심종목의 무제한 새 조회를 추가하지 않는다.

### DB / Frontend

- 실행 스냅샷에 후보군, 특징 시각·준비 상태, 제외 사유를 남긴다. 초기에 별도 전역 feature store를 만들 필요는 없다.
- `DAILY_DATA_MISSING`, `STALE_FEATURE`, `CANDLE_GAP`, `CALENDAR_UNVERIFIED` 등을 한국어로 표시한다.
- DB에 데이터가 있다는 사실과 전략에 필요한 데이터가 준비됐다는 사실을 구분한다.

### 완료 기준

- 동일 입력 스냅샷·설정으로 운영 평가와 재생 평가의 적격 여부·순위가 동일하다.
- 판단 이후 확정 또는 수신된 데이터가 추천에 들어가지 않는다.
- 일봉 필수 전략에서 미준비 종목은 매수 적격으로 승격되지 않는다.
- 누락 데이터가 있어도 과거 최고 탐지로 자동 대체하지 않는다.

## 7. Phase 10C: 모의 체결과 순손익 [P0]

### Backend / DB

- 기존 개인 투자 `trade` 원장을 변경해 모의 거래를 섞지 않는다. 별도 paper order/fill 기록을 만들고 포지션은 체결에서 계산한다. 규모가 작을 때 별도 포지션 테이블은 필수가 아니다.
- 계좌/실험 ID, run ID, 종목, 주문 시각, 방향, 수량, 주문가격·기한, 체결 시각·가격·수량, 비용, 체결 모형 버전, 청산 사유를 저장한다.
- 비용 설정은 매수·매도 수수료, 상품/시행일별 세금, 슬리피지를 구분한다. 실제 적용 요율은 구현 시 거래 환경에 맞춰 확인하고 실험 스냅샷에 고정한다.
- 신호 가격을 체결 가격으로 복사하지 않는다. 주문·평가 완료 이전의 캔들 시가로 체결시키지 않는다.
- 5분봉만 있으면 다음 실행 가능한 봉을 이용한 근사임을 표시한다. 당일 전체 VWAP나 해당 봉 전체 거래량 등 미래에 완성되는 값을 유리한 체결 근거로 사용하지 않는다.
- 손절 아래에서 시가가 형성되면 실행 가능한 가격과 불리한 슬리피지를 사용한다. 설정 손절률로 손실을 강제로 제한하지 않는다.
- 같은 봉에서 목표·손절을 모두 건드리면 모호성을 표시하고 기본 보수 결과와 대안 범위를 구분한다.
- 시간 청산, 미체결, 부분체결, 거래정지, 데이터 단절을 다룬다. 자료가 없을 때 가상의 정상 체결을 만들지 않는다.
- 같은 체결 데이터에서 거래별 손익과 계좌 손익을 산출하고, 실현손익과 미실현손익을 분리한다.

### 화면

- 후보 상태와 실제 모의 매수 여부를 구분한다.
- 신호 가격 / 체결 가격 / 청산 가격 / 총비용 / 순손익 / 청산 사유를 표시한다.
- 매수~당일 종가, 당일 종가~다음 시가, 다음 시가~청산 구간 수익을 분리한다. 구간 수익의 단순 합을 전체 수익으로 사용하지 않는다.

### 완료 기준

- -2% 손절 설정에서 -5% 시가 형성 시 -2%로 체결됐다고 계산되지 않는다.
- 미체결 주문은 승률·매매손익의 체결 거래 분모에 들어가지 않으며 별도 집계된다.
- 09:30 청산 이후 고가 상승이 해당 거래의 실현 이익으로 추가되지 않는다.
- 주문·체결 재처리 시 수량과 비용이 중복되지 않는다.

## 8. Phase 10D: 매수 적격 심사와 집중 위험 [P1]

### 신규 심사

- 거래 가능 여부 -> 데이터 준비 -> 일봉 추세 -> 최신 분봉 유지 -> 과열 -> 시장·업종 환경 -> 계좌 한도 순으로 평가하고 항목별 통과 근거를 저장한다.
- 종목을 발견한 스캐너 종류만으로 매수 자격을 부여하지 않는다.
- VWAP 회복 전략은 아래 -> 위 상태 전이를 실제로 확인한다. 다른 단순 강세 전략에 해당 조건을 억지로 적용하지 않는다.
- 기존 거래대금 만점 가산 대신 유동성 최소 조건과 주문금액 대비 체결 가능성을 검사한다. 거래량 급증도 시간대 차이를 감안한 비교를 검증한다.
- 기존 모멘텀 점수는 비교군으로 유지하고 신규 순위는 적은 수의 독립적인 기준부터 시작한다.
- 업종 데이터는 출처와 유효 시점을 기록한다. 현재 업종을 과거 전체에 무조건 소급 적용하지 않는다.
- 업종 미분류·시장 지표 결손 시 관련 필터가 정상 적용된 것으로 표시하지 않는다. 보류 또는 명시적 제한 모드로 처리한다.
- 변동성 기준 과열 필터와 시장 약세 시 매수 보류를 실험한다. 수익 개선 여부는 Phase 10F에서 판정한다.

### 화면 / DB

- '마감 후보' 화면에 관찰 / 적격 / 제외와 이유, 데이터 시각, 주문 가능 여부를 표시한다.
- 추천점수와 성공 확률을 구분한다. 검증 전에는 임의의 상승 확률을 제공하지 않는다.
- 위험은 데이터 결손, 가격 과열, 업종 집중, 계좌 노출 등 확인 가능한 항목으로 표시한다.
- 업종 매핑과 시장·업종 지표의 시점별 저장이 필요하다. KIS 등 공급자의 실제 API 제공 범위와 호출 예산은 구현 전에 확인한다.

### 완료 기준

- 과거 고득점 이후 현재 조건이 무너지면 적격으로 남지 않는다.
- 동일 업종 한도와 계좌 한도 초과 시 다음 순위 검토 또는 현금 유지가 결정적으로 재현된다.
- 후보가 없으면 필터를 자동 완화하지 않고 0건과 이유를 표시한다.

## 9. Phase 10E: 계좌 성과와 벤치마크 [P1]

- 모의 계좌의 초기 자본, 현금, 보유 수량, 평가가격, 비용, 외부 입출금, 데이터 상태를 날짜별 저장한다.
- 거래 없는 날도 계좌 시계열에 포함한다. 누락 평가일을 0% 수익으로 채우지 않는다.
- 순자산 수익률로 누적수익·계좌 MDD를 계산한다. 종목별 최저 수익률을 MDD라고 부르지 않는다.
- PF는 청산 거래의 순이익 금액 합 / 순손실 금액 절댓값 합으로 계산한다. 평균 이익/평균 손실 비율은 별도다.
- 샤프는 일별 초과수익, 소르티노는 명시된 최소요구수익률과 하방편차 기준으로 계산한다. 연율화 가정·무위험수익률·관측 수를 표시한다. 분모 0 또는 표본 부족은 미산출 상태다.
- 실제 보유 시간대와 투자 비중에 맞춘 KOSPI/KOSDAQ 및 업종 비교를 제공한다. 비투자 현금과 비용 처리도 명시한다.
- 같은 후보군에서 단순 순위 또는 시드 고정 무작위 선정한 비교군을 동일 체결 엔진으로 평가한다.
- 시장 초과수익과 회귀로 추정한 알파를 구분한다. 회귀 알파는 충분한 관측과 시장·업종 설명변수 및 불확실성이 확보된 뒤 제공한다.
- 업종 동반 하락, 야간 갭, 체결 지연, 거래정지, 연속 손실을 시나리오별로 시험한다. 계좌 파산확률을 몇 일치 승률만으로 계산하지 않는다.

완료 기준: 거래 원장과 계좌 잔액이 대사되고, 비교군에 같은 시각·비용·투자 가능 조건이 적용되며, 신뢰 가능한 계산이 불가능한 지표는 숫자를 꾸며내지 않는다.

## 10. Phase 10F: 독립 검증 및 전략 채택 [P2]

- 설정 변경마다 실험 ID를 부여한다. 전략 코드, 설정 해시, 데이터 버전, 기간, 시도 횟수와 실패 실험을 함께 보존한다.
- 개발 기간 -> 조정 기간 -> 최종 미사용 검증 기간을 시간순으로 구분한다. 포지션 보유 기간이 경계를 넘는 표본은 분리해 정보 누수를 막는다.
- 제한된 비교부터 진행한다: 기존 점수, 단순 상대 강도, 일봉 필터 추가, 최신 강세 유지 추가, 업종 제한 추가. 모든 조합 탐색으로 시작하지 않는다.
- 날짜 단위 상관과 연속성을 고려한 블록 재표집 등으로 순수익·초과수익의 불확실성을 평가한다. 50건이면 HIGH 같은 표본 수만의 신뢰도 등급을 제거한다.
- 표본이 적으면 신뢰구간을 안정적인 통계로 제시하지 않고 관측 부족 상태를 유지한다.
- 비용 상향, 주요 수익 날짜 제외, 업종별·시장 상태별 결과를 민감도 분석한다. 결과를 본 뒤 임의로 손실 날짜를 제외해 본 성과를 바꾸지 않는다.
- 다수 전략을 시험했다면 선택 편향을 고려한다. 채택 문턱과 평가 주기를 사전 고정해 매일 유의성이 나올 때까지 확인하는 방식도 피한다.
- 보유 연장·목표가 최적화는 초기 시간 청산 전략 평가 후 별도 실험으로 분리한다.

### 채택 판단

1. 정합성 검사가 통과하고 최신 단일 버전의 독립 검증 기록이 존재한다.
2. 비용 차감 후 기대수익 및 비교군 대비 개선의 불확실성이 사전 기준을 충족한다.
3. 특정 하루·종목·업종에 성과가 과도하게 의존하지 않는다.
4. 스트레스 손실과 계좌 MDD가 사전 위험 한도 이내다.
5. 설정을 고정한 실시간 모의운용에서도 재현된다.

관측 일수와 거래 건수만으로 자동 채택하지 않는다. 기술 구현 완료와 전략 우위 확인은 다른 완료 조건이다. 성과가 개선되지 않으면 전략 기각이 정상 결론이다.

## 11. Phase 10G: 운용 화면과 운영 통제 [P1~P2]

- 기존 `ClosingRecommendationApp.tsx` 흐름을 '후보 심사', '모의 거래', '성과 검증'으로 정리한다. 새 최상위 메뉴를 불필요하게 늘리지 않는다.
- 초보자 화면은 데이터 기준 시각, 적격 여부, 제외 이유, 실제 모의 매수 상태, 순손익을 우선한다.
- 점수 조정 입력은 실험 설정으로 이동하고, 운용 중 설정 변경은 새 버전·새 실행을 만든다.
- 장 종료 후 후보 평가는 재생 결과라는 표시와 함께 제공한다. 과거 가격의 신규 주문으로 연결하지 않는다.
- 기존 매도/보유 판단은 체결된 포지션에만 연결하고 초기 검증 전략에서는 보유 연장으로 자동 전환하지 않는다.
- 데이터 지연, 수집 실패, 주문 모형 미지원, 계좌 한도 초과 시 신규 모의 주문을 보류한다. 기존 포지션 관리와 신규 진입 중단은 별개로 처리한다.
- 모의운용 중 누적 손실·데이터 이상에 따른 중단 및 재개 기준을 기록한다. 실제 증권 주문 연동은 별도 승인된 개발 범위다.

## 12. DB 및 API 변경 원칙

| 대상 | 변경 방향 |
|---|---|
| `closing_recommendation_run` | 기존 감사 스냅샷 재사용, 실행·설정·시점·모드 메타데이터 추가 |
| `closing_recommendation` | run 연결, 실행별 유니크, 신호·평가 가격 의미 분리 |
| `overnight_performance` | 레거시 관측 성과 보존, 완결 상태·관측 구간 추가 |
| `overnight_position_decision` | 추천 재생성에 따라 삭제하지 않음, 신규 모의 체결 포지션과 연결 |
| 신규 모의운용 기록 | 계좌·주문·체결·일별 순자산, run 연결 및 비용 버전 |
| 시장/업종 자료 | 시점별 벤치마크, 업종 매핑·유효기간, 출처와 품질 |
| 실험 결과 | 기존 run 재사용 가능 범위를 먼저 확인하고 검증 구간·설정·결과 보존 |

- 마이그레이션은 새 버전 파일로 추가한다. 기존 Flyway 이력을 수정하지 않는다.
- 구버전 API를 즉시 제거하지 않고 run 기반 조회를 추가한 뒤 화면을 전환한다. 반환 의미가 달라진 필드는 새 필드/버전으로 제공한다.
- 평가 저장과 모의 주문 생성은 별도 명령으로 구분한다. 조회 GET은 KIS 수집·주문·성과 덮어쓰기의 부작용이 없어야 한다.
- 입력값 검증에는 시간 순서, 손절 부호, 수량·비중 한도, 비용 설정, 전략 필수 데이터 조건을 포함한다.
- 전략 버전 길이는 현재 DB 제약을 고려한다. 긴 설정은 JSON과 해시에 보관하며 버전명에 모든 설정을 넣지 않는다.
- 원본 실행 스냅샷과 모의 체결은 재현성에 필요한 기록이다. 대용량 중복 JSON은 인덱스·요약 조회·보관 정책으로 관리하고 화면의 빈번한 전체 조회를 피한다.

| 6 | 10F 독립 검증 | P2 | High | 4~7 개발일 | 10D, 10E 및 충분한 데이터 |
| 7 | 10G 화면·운영 통제 | P1~P2 | Medium | 3~5 개발일 | 단계별 점진 반영, 최종 10F |

합계 28~48 개발일은 한 명이 기존 코드를 활용한다는 가정의 설계 단계 추정이다. 외부 데이터 확보, 실제 전진검증 기간, 운영 중 발견되는 데이터 문제는 별도다. 세부 구현 조사 후 조정한다. 각 단계의 필수 화면 수정은 해당 단계에 포함하고 10G는 전체 흐름을 마무리한다.

첫 배포 범위는 10A로 제한하는 것을 권장한다. 과거 기록 보존과 성과 완료 상태를 고친 뒤 공통 평가·모의체결을 순서대로 연결한다. 10A 완료만으로 추천 수익성이 개선됐다고 판단하지 않는다.

## 14. 핵심 인수 테스트

| 사례 | 기대 결과 |
|---|---|
| 같은 날짜 재평가 및 요청 재시도 | 과거 run·체결 보존, 재시도 중복 없음 |
| 다음 날 오전만 데이터 존재 | 일일 종가 성과는 진행/불완전 상태 |
| 금요일 이후 월요일 휴장 | 거래 일정의 다음 개장일 사용 |
| 다음 거래일 데이터 누락 | 후속 날짜를 정상 다음 날로 오인하지 않음 |
| 일봉 0개 또는 최신 일봉 지연 | 해당 일봉 전략은 적격 처리하지 않음 |
| 15:15 판단에 15:15 이후 수신 특징 | FORWARD 입력에서 배제 |
| 과거 고점 탐지 후 현재 추세 붕괴 | 과거 고득점만으로 매수 적격 유지 불가 |
| 운영/재생에 동일 스냅샷 제공 | 후보, 통과 사유, 순위 동일 |
| 주문 전 봉 시가·지원하지 않는 세션 | 해당 가격으로 체결 불가 |
| 시가가 손절선 아래 / 목표·손절 동시 도달 | 갭 손실 반영 / 모호성 명시 |
| 주문 미체결·부분체결·중복 이벤트 | 체결 수량과 비용에 맞는 손익, 중복 반영 없음 |
| 당일 매매 없음 | 현금 포함 계좌 시계열 유지 |
| 시장·업종 데이터 없음 | 비교 불가/보류 표시, 초과수익 수치 생성 금지 |
| 과거 캔들 정정 후 재생 | 원본 실행 보존, 새 데이터 버전 결과 생성 |
