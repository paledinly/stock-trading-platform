# 장마감 오버나잇 추천 고도화 로드맵

기준일: 2026-09-04

이 문서는 현재 프로젝트를 `장마감 시점 매수 후 다음날 매도 또는 보유 판단을 지원하는 오버나잇 매매 의사결정 시스템`으로 발전시키기 위한 개발 순서를 정리한다.

현재 프로젝트에는 실시간 시세, 5분봉 저장, 실시간 레이더, Opportunity/Risk 점수, 장마감 추천, 다음날 성과 추적, 오버나잇 백테스트의 기반이 있다. 이후 개발은 새로운 추천 조건을 추가하기 전에 백테스트 정합성을 먼저 확인하고, 그 위에 이동평균선 기반 추세 판단과 다음날 매도/보유 판단을 얹는 순서가 권장된다.

## 1. 최종 목표

최종 목표는 단순히 오늘 강한 종목을 보여주는 것이 아니라 다음 흐름을 하나의 서비스로 연결하는 것이다.

```text
장중 탐지
  -> 장마감 추천 후보 선정
  -> 장마감 매수 기준 제공
  -> 다음날 장중 매도/보유 판단
  -> 실제 성과 및 백테스트 검증
  -> 추천 알고리즘 개선
```

핵심 사용자는 단기 오버나잇 매매 후보를 찾고, 다음날 수익 실현 또는 보유 연장 여부를 판단하려는 개인 투자자다.

## 2. 권장 개발 순서

```text
Phase 9A  백테스트 정합성 검증
Phase 9B  5분봉 이동평균선 Feature
Phase 9C  일봉 이동평균선 Feature
Phase 9D  이동평균선 기반 장마감 추천 점수 반영
Phase 9E  다음날 매도/보유 판단
Phase 9F  보유 연장 전략 백테스트
Phase 9G  추천 알고리즘 튜닝 및 비교 리포트
```

백테스트 정합성 검증을 가장 먼저 두는 이유는 이후 이동평균선이나 보유 판단을 추가해도 백테스트가 미래 데이터를 참조하거나 누락 데이터를 잘못 해석하면 성과 비교가 의미 없어지기 때문이다.

## 3. Phase 9A - 백테스트 정합성 검증

### 목적

오버나잇 백테스트 결과가 실제 매매 가능한 시점과 데이터 범위를 지키고 있는지 검증한다.

### 필요한 이유

추천 점수와 보유 판단 기능이 늘어날수록 백테스트 결과가 좋아 보여도 다음 문제가 섞일 수 있다.

- 추천 시점 이후 데이터를 점수 계산에 사용
- 다음 거래일 5분봉 누락
- 휴장일 또는 거래 없는 날 오판
- 같은 5분봉 안에서 목표가와 손절가가 동시에 도달
- 장마감 추천인데 15:30 이후 데이터를 사용
- 일봉 이동평균 계산에 추천일 이후 종가 포함

### 주요 기능

- 백테스트 데이터 커버리지 검사
- 5분봉 누락/중복 검사
- 비정상 OHLC 검사
- 미래 데이터 참조 검사
- 체결 가능성 검사
- 샘플 수와 종목 편중 검사
- 백테스트 정합성 리포트 API
- 백테스트 화면 내 정합성 상태 표시

### Backend 변경 범위

- `BacktestIntegrityService` 추가
- `BacktestIntegrityReport` DTO 추가
- 오버나잇 백테스트 응답에 integrity report 포함 또는 별도 API 제공
- 5분봉 간격 검사 유틸 추가

### Frontend 변경 범위

- 오버나잇 백테스트 결과 하단에 `백테스트 정합성` 패널 추가
- `통과`, `경고`, `실패` 상태 표시
- 문제 항목별 상세 메시지 표시

### DB 변경 여부

초기에는 불필요하다. 검증 결과를 이력으로 저장하려면 추후 별도 테이블을 추가한다.

### 난이도

Medium

### 완료 기준

- 미래 데이터 참조 여부를 코드 레벨에서 설명 가능
- 누락/중복 5분봉을 리포트로 확인 가능
- 목표/손절 동시 도달 케이스를 `AMBIGUOUS` 또는 보수적 처리로 구분
- 백테스트 결과에 신뢰도 상태가 함께 표시됨

## 4. Phase 9B - 5분봉 이동평균선 Feature

### 목적

장마감 시점의 단기 진입 상태를 판단하기 위해 5분봉 기준 이동평균선을 계산한다.

### 필요한 이유

현재 장마감 추천은 VWAP, 거래량, 거래대금, 체결강도, 고점 근접도를 사용한다. 여기에 5분봉 이동평균선을 추가하면 장막판에 단기 흐름이 무너진 종목을 감점하고, 단기 정배열이 유지되는 종목을 더 높게 평가할 수 있다.

### 주요 기능

- MA5, MA20, MA60 계산
- 현재가와 MA5/MA20/MA60 이격도 계산
- MA5 > MA20 > MA60 정배열 여부
- MA5/MA20 골든크로스 여부
- MA20 지지 후 반등 여부
- 장마감 전 MA20 이탈 여부

### Backend 변경 범위

- `MovingAverageFeature` 또는 `IntradayMaFeature` 추가
- `StockCandleRepository`에 최근 5분봉 조회 메서드 추가
- 장마감 추천과 백테스트에서 동일 계산 로직 재사용

### Frontend 변경 범위

- 추천 근거에 `5분봉 MA5 > MA20`, `MA20 지지`, `MA20 이탈` 표시
- 차트에 MA5, MA20, MA60 라인 표시 검토

### DB 변경 여부

초기에는 불필요하다. 추천 시점의 계산 결과는 기존 reason JSON에 저장할 수 있다.

### 난이도

Medium

### 완료 기준

- 장마감 추천 시점 이전 5분봉만 사용
- 백테스트에서도 동일한 MA feature 사용
- 추천 근거와 위험 근거에 MA 항목 표시

## 5. Phase 9C - 일봉 이동평균선 Feature

### 목적

종목의 큰 추세를 판단해 하락 추세 종목이나 구조가 무너진 종목을 줄인다.

### 필요한 이유

5분봉만 사용하면 당일 반짝 수급이 강한 종목이 추천될 수 있다. 일봉 이동평균선을 사용하면 큰 추세가 살아 있는 종목을 우선하고, 하락 추세 종목을 감점할 수 있다.

### 주요 기능

- 일봉 MA5, MA20, MA60 계산
- 종가 > MA20 여부
- MA5 > MA20 여부
- MA20 기울기
- MA60 아래 종목 감점
- 일봉 이격 과열 감점

### Backend 변경 범위

- 일봉 데이터 확보 방식 결정
- 일봉 candle 저장 구조 추가 또는 기존 `stock_candle.timeframe`에 `1D` 확장
- `DailyTrendFeature` 추가

### Frontend 변경 범위

- 추천 근거에 `일봉 20일선 위`, `일봉 정배열`, `20일선 상승` 표시
- 위험 근거에 `일봉 20일선 아래`, `일봉 과열` 표시

### DB 변경 여부

필요할 가능성이 높다. 권장 방식은 기존 `stock_candle`의 `timeframe`을 활용해 `1D` 데이터를 저장하는 것이다.

### 외부 API 필요 여부

필요하다. KIS 일봉 API 또는 과거 시세 API 연동이 필요하다.

### 난이도

Medium~High

### 완료 기준

- 추천일 기준 미래 일봉 데이터가 계산에 섞이지 않음
- 휴장일을 고려한 최근 N거래일 MA 계산 가능
- 일봉 추세가 추천 점수 또는 위험 점수에 반영 가능

## 6. Phase 9D - 이동평균선 기반 장마감 추천 점수 반영

### 목적

기존 장마감 추천 점수에 분봉/일봉 이동평균선 feature를 반영한다.

### 권장 점수 방향

기존 점수를 완전히 대체하지 않고 가산/감점 방식으로 확장한다.

```text
기존 점수
  + 일봉 추세 점수
  + 5분봉 정배열 점수
  + MA20 지지/반등 점수
  - 일봉 하락 추세 위험
  - 5분봉 MA20 이탈 위험
  - MA 이격 과열 위험
```

### 필요한 이유

무조건 제외 조건이 많아지면 후보가 너무 줄어든다. 따라서 초기에는 제외보다 점수 가산/감점으로 적용하고, 백테스트 결과를 본 뒤 강한 필터로 승격하는 방식이 좋다.

### Backend 변경 범위

- `ClosingRecommendationScorer` 확장
- recommendation reason JSON에 MA factor 추가
- risk reason JSON에 MA risk factor 추가
- 전략 버전 변경

### Frontend 변경 범위

- 추천 카드의 점수 근거 한글 표시 항목 확장
- 기존 방식과 MA 반영 방식 비교 결과 표시 검토

### DB 변경 여부

기존 JSON 저장 구조를 사용하면 필수 변경은 없다. 전략 버전 관리를 명확히 하려면 version 값만 갱신한다.

### 난이도

Medium

### 완료 기준

- 기존 방식과 MA 반영 방식의 백테스트 비교 가능
- 추천 근거에서 MA가 점수에 어떻게 기여했는지 확인 가능
- MA 데이터가 부족한 종목은 명확히 감점 또는 중립 처리

## 7. Phase 9E - 다음날 매도/보유 판단

### 목적

장마감 추천 종목을 매수한 뒤 다음날 장중에 매도할지, 더 보유할지 판단한다.

### 필요한 이유

프로젝트의 실전 가치는 추천에서 끝나지 않고 다음날 대응까지 이어질 때 커진다. 목표 수익률에 도달한 종목이라도 수급과 추세가 유지되면 보유 연장을 제안할 수 있고, 반대로 상승 후 힘이 꺾이면 매도 권고를 줄 수 있다.

### 판단 상태

```text
DATA_PENDING     판단 대기
HOLD             보유
EXTEND_HOLD      보유 연장
TAKE_PROFIT      익절 권고
SELL_WARNING     매도 주의
STOP_LOSS        손절
```

### 보유 연장 조건 예시

- 현재 수익률이 플러스
- 현재가가 VWAP 위
- 5분봉 MA5 > MA20 유지
- 5분봉 MA20 이탈 없음
- 고점 대비 낙폭이 작음
- 체결강도 양호
- 거래량이 유지됨

### 매도 권고 조건 예시

- VWAP 이탈
- 5분봉 MA20 이탈
- 목표 수익률 도달 후 음봉 전환
- 고점 대비 낙폭 확대
- 체결강도 약화
- 손절 기준 도달

### Backend 변경 범위

- `OvernightPositionDecision` 도메인 추가
- `OvernightPositionDecisionService` 추가
- 추천 종목의 다음날 실시간 quote, feature, 5분봉 MA 기반 판단
- 판단 reason JSON 저장
- 판단 이력 조회 API 추가

### Frontend 변경 범위

- 장마감 추천 카드에 현재 판단 상태 표시
- `보유 연장`, `익절 권고`, `매도 주의`, `손절` 상태 배지
- 판단 근거 한글 설명 표시
- 현재가, 현재 수익률, VWAP, MA 상태 표시

### DB 변경 여부

필요하다.

권장 테이블:

```text
overnight_position_decision
- id
- recommendation_id
- evaluated_at
- current_price
- return_rate
- decision
- reason_json
- vwap
- ma5
- ma20
- ma60
- target_hit
- stop_hit
- calculation_version
```

### 난이도

Medium~High

### 완료 기준

- 추천 종목별 다음날 실시간 판단 가능
- 판단 이유가 JSON과 UI에 함께 남음
- 목표 도달 이후에도 보유 연장 여부를 판단 가능

## 8. Phase 9F - 보유 연장 전략 백테스트

### 목적

다음날 바로 매도하는 전략과 보유 연장 전략의 성과를 비교한다.

### 필요한 이유

보유 연장은 수익을 키울 수 있지만 수익을 반납할 수도 있다. 따라서 실전 적용 전 반드시 전략별 성과를 비교해야 한다.

### 비교 전략

```text
A. 다음날 시가 매도
B. 다음날 종가 매도
C. 목표 수익률 도달 시 매도
D. VWAP 이탈 시 매도
E. 5분봉 MA20 이탈 시 매도
F. 목표 도달 후 MA/VWAP 유지 시 보유 연장
```

### Backend 변경 범위

- 백테스트 전략 enum 추가
- 보유 연장 시뮬레이션 로직 추가
- 동일 5분봉 내 목표/손절 동시 도달 처리 정책 추가
- 전략별 성과 summary 계산

### Frontend 변경 범위

- 전략별 백테스트 비교 표
- 승률, 평균 수익률, 최대 낙폭, 손익비, 샘플 수 표시
- 정합성 리포트와 함께 표시

### DB 변경 여부

초기에는 불필요하다. 백테스트 실행 결과를 저장하려면 별도 테이블을 추가한다.

### 난이도

High

### 완료 기준

- 최소 3개 이상 매도 전략 성과 비교 가능
- 보유 연장 전략의 평균 수익률과 최대 낙폭 확인 가능
- 정합성 경고가 있는 결과와 정상 결과를 구분 가능

## 9. Phase 9G - 추천 알고리즘 튜닝 및 비교 리포트

### 목적

기존 추천 방식, MA 반영 방식, 보유 판단 방식의 성과를 비교하고 실제 사용할 기본 전략을 정한다.

### 주요 비교 기준

- 추천 건수
- 데이터 누락률
- 시가 승률
- 종가 승률
- 평균 시가 수익률
- 평균 종가 수익률
- 평균 최고 수익률
- 평균 최대 낙폭
- 목표 도달률
- 손절 도달률
- 손익비
- 종목 편중도
- 날짜 편중도

### Backend 변경 범위

- strategy version별 성과 비교 API
- 조건 조합별 summary
- minimum sample size와 confidence 계산

### Frontend 변경 범위

- 전략 비교 리포트 화면
- 추천 알고리즘 버전별 성과 표시
- 운영 기본값 후보 표시

### DB 변경 여부

전략 버전별 실행 결과를 저장하려면 필요하다. 초기에는 기존 추천/성과 테이블과 백테스트 API 응답으로 시작 가능하다.

### 난이도

Medium~High

### 완료 기준

- 현재 운영 추천 방식과 후보 알고리즘을 같은 기간으로 비교 가능
- 샘플 수가 부족한 결과는 낮은 신뢰도로 표시
- 추천 기본 전략을 수치 기반으로 선택 가능

## 10. 개발 우선순위

### P2 - 서비스 차별화

### P3 - 장기 확장

## 11. 구현 시 주의사항

### 미래 데이터 참조 금지

추천 점수 계산은 추천 시점에 알 수 있는 데이터만 사용한다.

```text
장마감 추천 점수 계산 데이터 <= 추천일 15:30
다음날 성과 계산 데이터 >= 다음 거래일 09:00
다음날 보유 판단 데이터 <= 판단 시각
```

### 백테스트와 실시간 로직 재사용

실시간 추천과 백테스트가 서로 다른 계산 함수를 쓰면 결과가 맞지 않는다. 이동평균선 feature, 추천 점수, 보유 판단은 가능한 한 순수 계산 컴포넌트로 분리해 실시간과 백테스트에서 함께 사용한다.

### 강한 필터보다 점수화 우선

초기에는 이동평균선 조건을 무조건 제외 조건으로 쓰지 않는다. 먼저 가산/감점으로 반영하고, 백테스트에서 명확히 유리한 조건만 강한 필터로 승격한다.

### 데이터 부족 처리

MA60처럼 긴 데이터가 필요한 feature는 초기 데이터가 부족할 수 있다. 이 경우 임의 값을 만들지 말고 `DATA_INSUFFICIENT`, `NEUTRAL`, `PENALIZED` 같은 정책을 명확히 둔다.

### 체결 가정 명시

백테스트는 실제 주문 체결과 다를 수 있다. 특히 같은 5분봉 안에서 목표가와 손절가가 모두 도달하면 순서를 알 수 없으므로 `AMBIGUOUS`로 표시하거나 보수적으로 손절 우선 처리한다.

## 12. 권장 다음 작업

가장 먼저 진행할 작업은 `Phase 9A 백테스트 정합성 검증`이다.

권장 세부 순서:

```text
1. 오버나잇 백테스트 결과에 integrity report DTO 추가
2. 5분봉 누락/중복/비정상 OHLC 검사 구현
3. 미래 데이터 참조 경계 검사 구현
4. 목표/손절 동시 도달 ambiguity 검사 구현
5. 백테스트 화면에 정합성 패널 추가
6. 테스트 추가
```

이 작업이 끝나면 이동평균선 기능을 추가했을 때 기존 방식보다 안정적인지 더 신뢰할 수 있는 방식으로 비교할 수 있다.
