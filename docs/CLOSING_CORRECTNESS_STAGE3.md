# 마감추천 정합성 3단계 (2026-09-14)

## 변경

전략 버전: closing-recommend-v5-asof. 점수 가중치, 최소 최종점수 55, 최소 확정봉 4개/20분, BROAD 관찰 전용 정책은 유지한다.

1. 캔들 coverage는 첫 봉~마지막 봉 시간 차가 아니라 탐지 직전 5분 경계에 연결된 연속 확정봉 수 × 5분이다. 중복 시작시간은 한 번만 인정하며 공백이 있으면 거기서 중단한다.
2. 봉 시작시간뿐 아니라 종료시간(start+5분)이 탐지 시점과 생성 평가 종료시점 이하인지 확인한다. 생성 시점에 뒤늦게 쌓인 미래 봉으로 과거 탐지의 수집 부족을 보완하지 않는다.
3. 종목별 모든 탐지를 평가한 뒤 SELECTED 적격 > WATCH > EXCLUDED 순으로 대표를 선택한다. 같은 단계에서는 최종점수, 탐지시간, detection ID 순이다. 최신 고위험/누락 신호가 다른 적격 탐지를 숨기지 않는다. 대표 선택과 생성 결과/평가 audit에 동일한 신호를 사용한다.
4. 분봉 MA DB 조회 상한을 평가시간-5분으로 변경하고 확정 여부/종료시간도 검사한다. 기존 당일 일봉 배제 정책은 유지한다.
5. 미래 날짜 생성은 INVALID_REQUEST/HTTP400으로 거절한다. 웹 오늘/기간 기본값은 Asia/Seoul 날짜를 사용한다.

## 처리량 및 호환

coverage DB 조회는 종목당 한 번이며 메모리에서 각 탐지 시점의 연속성을 확인한다. 다수 탐지를 실제 평가하므로 기존 최신 1건 평가보다 MA 조회량은 늘어날 수 있다. tick 경로는 변경하지 않는다. 대표 한 건을 audit에 기록하는 기존 응답 구조와 기존 API를 유지한다.

신규 migration/환경변수는 없다. 기존 추천/실행 audit는 자동 재계산하지 않는다. 새 생성 결과부터 새 전략 버전이 기록된다. 생성 버튼의 기존 날짜별 추천/성과/포지션 결정보기 데이터 교체 동작은 유지되므로 성과 축적된 날짜의 재생성에 주의한다.

## 검증 및 한계

회귀 테스트: 연속 확정봉 적격, 중간 gap, 탐지 이후 봉 제외, 적격 이전 신호와 고위험 최신 신호, 미래 날짜 사전 차단, 미종료 봉 MA 제외, audit 저장/읽기, BROAD 관찰 전용 유지.

이 단계는 데이터/선택 정합성 개선이며 수익률 향상 검증은 아니다. 적격 이전 신호를 사용한다는 뜻이지 현재 시점에도 유효하다는 보장은 아니다. 기존 탐지시점 Feature Snapshot과 가격을 기준으로 평가한다. 신호 유효기간/장마감 직전 재평가는 별도 규칙과 실제 축적 데이터를 바탕으로 검증해야 한다.

stock_candle은 수정 가능한 현재 상태 테이블이다. 과거 시점에 아직 수신되지 않았던 backfill 및 이후 revision을 완전 복원하는 point-in-time 저장소는 아니다. 봉 종료시간 기준의 미래 가격 혼입은 막지만, 엄격한 historical replay 검증에는 당시 candle revision/availability 보존이 추가로 필요하다.

후속 범위는 비동기 보강 큐와 장중 실제 수집 검증이다. 이번 작업은 운영 DB 직접 변경, 서비스 재시작 또는 git commit/push를 수행하지 않는다.
