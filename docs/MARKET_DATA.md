# Market Data

Phase 3 호가 10단계는 기본 5초 간격의 제한된 REST 표본이며, 대량체결은 기존 WebSocket 체결에서 집계한다. 장중 수집만 허용하고 불연속 체결 방향은 UNKNOWN으로 남긴다. 기본 비활성이고 추천 점수는 유지한다. [설정 및 관측 한계](MICROSTRUCTURE.md).

Phase 2 외국인·기관 가집계 및 KRX 프로그램 누적 수급은 별도 활성화 시 Trajectory의 investorFlow로 제공한다. 수량 단위, 원천/수신시각, 30분 관측 변화량의 의미 및 제한은 [수급 관측](INVESTOR_FLOW.md)을 따른다. 기존 Intraday 입력에는 자동 연결되지 않는다.

## 장마감 Trajectory (V28)

기존 체결에서 1분 Aggregate와 기본 5분 간격의 대금/순위/VWAP/체결 추세·실제 지수 상대강도 Snapshot을 만든다. 기본 비활성 SHADOW 수집이다. 시간·결측·단위는 [장마감 Trajectory](CLOSING_TRAJECTORY.md)를 따른다. 각 실행의 저장된 평가 기준 이후 자료를 소급 사용하지 않는다. 신규 v9 기준은 15:15이며 기존 v8의 15:00 기준은 유지된다.

## Intraday 입력 원장과 결측

장중 연구를 활성화하면 기존 수집 체결·공통 Feature·gateway 수신시각·Intraday 평가시각·당시 종목 적격성·전체 실험 설정을 `intraday_input`에 저장한다. 원천 발생시각, 수신시각, 실제 평가시각은 각각 보존한다. 추천시각을 과거 체결시각으로 소급하지 않는다.

VWAP는 `MarketFeatureEngine` 결과를 사용하되 당일 누적 거래대금/거래량 원천이 있는 경우만 유효하다. 1/3/5/10/15/30분 수익률과 1/5/15/30분 거래량·대금은 원장 내 누적값 차이로 계산한다. 동일 길이 직전 구간과의 배수이며 최근 N일 동일 시간대 RelativeVolume과 다르다. 기준 관측은 cutoff 이하의 가장 가까운 값으로, 최대 허용 간격 내에서만 사용한다. 실제 틱 고저로 순서 있는 구간을 구성하므로 별도의 KIS 1분봉/3분봉 수집이나 기존 확정 5분봉 수정은 하지 않는다.

전일종가 대비 등락률, 동일 시간대 RVOL, 지수/업종 RS, Regime, 실측 호가/Spread, 호가 불균형, VI 상태·횟수, 상하한가 거리, 투자위험 및 신규상장 이력은 현재 `unavailable`이다. VI 기준가격만으로 VI 발동 상태를 추정하지 않는다. 결측을 중립 값이나 가점으로 채우지 않으며 `require-complete-risk-data=true`이면 추천을 차단한다. 기본 연구 모드에서는 위험요인으로 표시한다.

신규 원장 전의 저장 5분봉으로 실제 수신시각이나 1/3분 성과·목표/손절 선후관계를 복원할 수 없다. Intraday 공식 재생은 수신 원장이 있는 범위만 지원한다.

## 공급원

- KIS WebSocket: 실시간 체결
- KIS REST: 현재가, 과거 분봉, 일봉, 거래량/거래대금 랭킹
- PostgreSQL: 확정봉, 탐지, 추천과 성과 이력

## 실시간 시각

일반 틱의 계산·시세 배포는 DB 트랜잭션 없이 처리한다. 확정봉이 포함되면 해당 봉 저장과 Scanner 평가를 명시적 트랜잭션으로 완료한 후 관측 이벤트를 발행한다. 기존 외부 트랜잭션 내 호출은 해당 트랜잭션 커밋 이후 리스너가 실행되고, 트랜잭션이 없는 일반 틱은 즉시 리스너로 전달된다. 미확정봉은 기존 평가기에서 추천 불가인 입력이므로 DB 조회 없이 이탈 상태 bookkeeping만 갱신한다. 확정봉은 기존 종목/봉/설정을 새로 조회하므로 별도 캐시나 무효화 지연이 없다.

실시간 WebSocket 체결은 첫 text 콜백 진입 시각을 수신시각으로 보존한다(분할 메시지는 첫 조각 기준). 파싱 후 단일 FIFO 작업자가 처리하며 수신 콜백에서는 DB/Redis/SSE 작업을 수행하지 않는다. 과거 입력 원장의 수신시각은 기존 의미인 MarketDataService 진입 시각 그대로 유지한다.

처리 큐는 기본 20,000틱이며 `MARKET_REALTIME_PROCESSING_QUEUE_CAPACITY`로 조절한다. 초과 시 새 틱을 버리고 `processingDropped`에 기록한다. 이후 각 종목의 첫 수락 입력에 `dataLoss`를 전달한다. 재연결과 처리 실패도 연속성 손실로 전달하며 장중추천 워밍업과 1분 집계의 완전성에 반영한다. 큐는 메모리이므로 프로세스 강제 종료 시 복구되지 않는다. 정상 종료는 최대 5초 대기 후 남은 대기 작업을 취소한다.

SSE 발행은 작업자에서 클라이언트별 bounded queue(4,096 이벤트)에 넣기만 하고, 실제 전송은 클라이언트별 가상 스레드가 한다. 느린 브라우저/프록시 소켓이 틱 처리를 멈추지 않는다. 큐가 넘친 클라이언트는 연결을 끊고 브라우저가 `Last-Event-ID`로 재연결해 replay 버퍼 범위 안에서 이어 받는다. 2026-10-13 개장 직후에는 이 전송이 작업자에서 동기로 수행되어 Vite 프록시 연결의 쓰기 대기로 처리 큐가 가득 차고 장중추천 전 종목이 `STALE_OR_LOST_INPUT`이 되었다.

MarketTick은 원천 거래일과 발생시각, 서버 수신시각을 구분한다. 파서가 확인할 수 없는 날짜나 숫자를 현재 날짜 또는 0으로 대체해서는 안 된다. 오류 카운터에는 파싱 외 처리 예외가 포함될 수 있어 전체 틱 손실률과 동일하지 않다.

## 5분봉

정규장 bucket은 09:00부터 15:25까지다. 15:30 종가 체결은 마지막 15:25 봉에 반영한다. 확정 후 도착한 늦은 틱, 중복 틱, 과거 bucket 틱은 확정봉을 부분 데이터로 재생성하지 않는다.

과거 분봉 backfill은 누락 구간 보완용이다. 실시간 당시 수신 여부를 증명하지 못하므로 15시 공식 판단의 원자료로 소급 사용하지 않는다.

## Feature

현재 Feature 버전은 market-feature-v2다. 진행 중 봉과 확정봉은 같은 의미로 비교하지 않는다. 거래량 배수는 동일 길이의 유효 baseline을 요구하며 결측, 재시작, 세션 불연속을 구분한다.

- VWAP은 당일 누적값과 대체값의 품질을 구분한다.
- 체결강도와 직전 틱 증분은 고정 시간창 지속 수급과 동일하지 않다.
- 과거 turnoverRatio 이름이 거래대금 배수를 뜻하는 경로가 있어 필드 정의를 확인한다.
- VI 기준가와 거래정지는 KIS 원천 필드 및 종목 상태와 함께 검증한다.

## 구독과 후보

관심종목은 사용자 목록이고 실시간 구독은 KIS 한도 내 운영 자원이다. 관심종목에 추가하는 것만으로는 실시간 슬롯을 사용하지 않으며, 사용자가 실시간 고정한 종목만 WATCHLIST 구독을 사용한다. 기본 고정 한도는 10개다.

Broad 후보는 랭킹과 제한된 상세 현재가 조회로 만들어져 QUOTE_FAILED가 많으면 품질이 낮아질 수 있다. Precision 후보는 제한된 종목을 더 정밀하게 관측한다. Precision 교체는 기본 14:35에 동결하여 15시 평가 전 최소 관측 시간을 확보한다. 동결 후 재시작하면 늦게 새 후보를 채워 넣지 않는다.

일봉은 WebSocket 슬롯과 무관한 KIS REST 경로로 준비한다. 기본 08:10 준비 외에 14:25와 14:35에 당일 ACTIVE Precision 종목을 우선 보완하며, 평가일 직전 거래일까지의 일봉만 요청한다.

전역 마지막 틱만으로 모든 종목이 최신이라고 판단하지 않는다. 종목별 최신성, 봉 수, 연속성, 확정 여부, 원천/수신 시각과 거래가능 상태를 각각 확인한다.
